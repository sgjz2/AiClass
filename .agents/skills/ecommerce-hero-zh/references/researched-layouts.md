## 2. 实际展示图的拆解与改编

### 榴莲主图：包装与内容物形成一个视觉组

观察：纵向画面，上方居中标题与细小补充信息；中下部由右后方的大包装、前方切开的果肉及较小物件形成高低和前后关系。米白背景、橄榄色包装与黄色果肉形成集中色彩。大部分明暗柔和，商品落在台面或台座上。这里观察的是可见效果，未获知真实灯具或摄影参数。

迁移：当包装和可见内容物共同帮助购买决策时，把二者组成一个主视觉组，用尺度和遮挡区分主次；先预留标题区再处理道具。不要为了丰富画面重复堆多个相同商品。若只有单个杯子或相机，改用完整商品与有依据的局部细节、商品与真实使用动作的关系，不虚构内容物或套用水果台座。

边界：这张图没有促销价格、日期、CTA，不能直接当我们的全信息促销模板；正式任务应重新安排交易信息。包装文字和商业事实不移植到新商品。该图仅作仓库展示，未核实是在售广告或真实拍摄。

## 3. 可选排版机制：先选理由，再确定坐标

以下是基于上述文件与观察的本项目改编，不是外部仓库原有成品模板，也不是固定配色。

| 机制及来源 | 适用任务 | 执行决定 | 拒绝条件 |
| --- | --- | --- | --- |
| 数值与商品形成主次；frontend-posters 的 Product Precision 预设与层级方法 | 一个已证实参数就是主利益，且受众能理解 | 一个主数值与商品组成第一层；数值旁贴近放解释文字和单位；品牌、辅助点与交易条件形成较弱层级 | 数值无依据；放大数字仍无法解释用户收益；价格和参数同样巨大而争夺焦点 |
| 包装/整体与内容/细节形成视觉组；榴莲展示图 | 包装识别、材质或细节能支持购买理由 | 大小、前后和遮挡建立关系；标题区提前留出；实际细节素材优先。生成性能示意须清楚标注 | 多物件没有购买理由；包装或关键细节被遮住；把生成图当实测证据 |
| 图文分区；designskills 的 split/grid 与 frontend-posters 的对齐方法 | 必需文案较多，或产品照片需较完整保留 | 照片区与信息区分工，保持一个主对齐轴；用主标题/利益建立两区关系；辅助文案归组而非等权卡片 | 两区毫无关系；商品像孤立贴纸；分区只能靠遮罩掩盖差的光影 |
| 克制的编辑式构图；frontend-posters 的 quiet-luxury 路线 | 品牌定位与材质细节比即时折扣更重要 | 用留白、一次有目的的裁切和对齐的次要信息维持张力；依赖商品尺度与材质，不叠加多种豪华符号 | 廉价促销需要密集交易信息；减少元素后主价值也消失 |

预设原文件：[Product Precision 等预设](https://github.com/caorachel-lab/frontend-posters/blob/main/references/style-presets.md)、[Quiet Luxury](https://github.com/caorachel-lab/frontend-posters/blob/main/references/style-quiet-luxury.md)。不能只读预设名称就声称已经使用了图像参考。

## 4. 每次任务的最低执行动作

1. 先判断参考是否与本次版位、画幅、信息量相近。选少量参考，给每张一个主职责：构图、光影材质或排版；商品身份单独记录。
2. 实际打开图像。记录标题形状、商品轮廓与大小关系、对齐轴、留白、主光可见效果和交易信息位置。只读描述或源码时记录为“方法参考”；看不到图就不填写图像观察。
3. 写一行迁移决定：`参考中的可见机制 → 本商品为什么适用 → 具体构图/字体/光影决定 → 对应生成指令或 layout 图层`。不能止于“参考了高级感”。
4. 有需要且工具支持时将所选图作为输入，明确各图职责；不支持或图像不可用时记录仅经观察转成规格，不能写成已传入模型。网页图片不因看过就成为当前工具可读取的本地素材。
5. 用相同文案与商品资料做机制不同的小样。先比较标题轮廓、商品体量和主利益，再补细节。可由 Agent 生成粗排或用代码合成，不要求组员手绘。
6. 实际导出完整图和整图缩放预览：先看一眼识别，再看支持信息，最后核对条件与行动。声明有意遮挡；检查其余信息块是否相撞、关键内容是否越过安全边界。HTML 导出须等字体加载。中英文分别调整换行与字距，中文不直接套英文 tracking。
7. 与参考并排评审具体关系、材质和层级；无法提供并排图时说明，保留已查看来源。记录哪项达到、哪项仍有差距。没有新的实际成片不宣称专业效果已经提升。

执行卡可合并到 brief：`reference_id / observed_mechanism / fit_reason / layout_decision / light_decision / tool_input_status / output_layer_or_prompt / review_evidence`。每条须落到实际决定，而不是只填表。

## 5. 我们案例的使用说明

NORI：课程资料的 12 小时保温保冷可采用数值机制。通勤到轻户外的关系还需真实场景或动作支撑；数字本身不证明“轻装”。标题、12h 与价格须明确主次，日期仍可读。

相机：整体/细节关系可表达用户提出的高像素方向；现有信息没有可核实的像素数，不能照数值机制编数。真实样张优先；生成放大细节只能作为已标注的创意示意。两例是迁移说明，不能据此认定成片已经改善。
